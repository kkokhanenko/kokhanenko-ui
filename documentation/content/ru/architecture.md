# Архитектура и границы

## Основной принцип

`@kokhanenko/ui` — UI-слой, а не framework приложения. Компоненты получают
данные через props и возвращают намерение пользователя событиями. Поэтому один
и тот же набор компонентов можно подключать к приложениям с разными API,
маршрутами, предметными областями и визуальными темами.

## Что принадлежит библиотеке

- разметка и визуальные состояния компонента;
- клавиатурное управление и ARIA-атрибуты;
- локальное интерактивное поведение: открыть панель, выбрать пункт, изменить
  порядок или ширину;
- типизированные контракты props, событий и slots;
- семантические CSS-токены и нейтральные значения по умолчанию.

## Что принадлежит приложению

- маршруты и переходы;
- загрузка данных и вызовы API;
- серверная сортировка, фильтрация и пагинация;
- авторизация и идентификатор пользователя;
- постоянное хранение настроек интерфейса;
- брендовая палитра и расположение переключателя темы;
- бизнес-правила и предметные виджеты.

## Структура пакета

```text
src/foundation       токены и opt-in base styles
src/controls         базовые интерактивные контролы
src/data             таблица и связанные контролы
src/feedback         сообщения и подсказки
src/overlays         модальное окно и меню действий
src/shell            оболочка приложения
src/preferences      транспорт-независимые UI-настройки
src/composables      переиспользуемое внутреннее поведение
```

## CSS и tree-shaking

Каждый subpath entry импортирует только собственный CSS. Например,
`@kokhanenko/ui/button` не подключает таблицу, модалку или shell. Поле
`sideEffects` в `package.json` сохраняет CSS при tree-shaking.

## Controlled components

Большинство компонентов контролируемые: библиотека не меняет переданное
состояние сама, а отправляет `update:*`. Приложение должно принять значение и
передать его обратно.

```xml
<KTabs v-model="activeTab" :options="tabs" />
```

Для серверных данных это особенно важно: событие обновляет query state,
приложение выполняет запрос, а таблица показывает полученный результат.

## Публичное и внутреннее API

Публичными считаются только entry points из `package.json#exports`. В частности,
`KSidebarNav`, `KTopbar`, `useFloatingPanel` и `useDismissableLayer` используются
внутри библиотеки и не являются стабильными импортами для приложений.
